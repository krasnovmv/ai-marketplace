# Личное зеркало плагинов

Проект готовит каталог внешних плагинов для Claude Desktop и поддерживающего локальные плагины режима ChatGPT desktop. Пакеты копируются из точных Git-ревизий без запуска и исправления их кода. OpenSpec используется отдельно для разработки и не входит в зеркало.

## Что внутри

Состав источников задаёт [config/upstreams.json](config/upstreams.json), а принятый на текущий commit набор — сгенерированные каталоги для [Claude](.claude-plugin/marketplace.json) и [ChatGPT](.agents/plugins/marketplace.json). Происхождение, ревизии и контрольные суммы каждого принятого пакета находятся в [metadata](metadata).

Весь выбранный пакет копируется целиком, поэтому в зеркало попадают и экспериментальные навыки upstream; доступность конкретного навыка определяется manifest плагина и клиентом. Оригинальные лицензии сохраняются в составе пакетов.

## Статус

Реализованы локальный конвейер и GitHub Actions: тесты и проверка каталогов на Windows/Linux, подготовка обновлений отдельным PR. Автоматического слияния нет. Проверка установки и обновления в настольных клиентах ещё предстоит; ежедневный sync включается после неё.

Внутренние ссылки на файлы и каталоги разрешены. Проверяется вся цепочка; выход за пределы пакета, циклы, отсутствующие цели и junction блокируют запуск. Точные ревизии и Git modes принятых ссылок указаны в `metadata/<name>.json`.

## Установка и проверка

Требуются Node.js 22+, npm и Git, доступные через PATH. Runtime-зависимостей нет. CI использует Node.js 22 и проверяет Windows/Linux.

```sh
npm ci --ignore-scripts
npm test
npm run validate
```

Тесты используют встроенный Node test runner и временные локальные Git-репозитории, без upstream-сети. Запускается только папка `test/`: тесты зеркалируемых плагинов не исполняются. Если npm недоступен, эквиваленты команд: `node --experimental-strip-types --test test/*.test.ts` и `node --experimental-strip-types src/cli.ts <команда>`.

## Команды

| Команда | Результат |
|---|---|
| `npm run validate` | Без сети и записи проверяет config, принятые пакеты, metadata и каталоги. Сообщает о локально определяемом расхождении желаемого и принятого состава. |
| `npm run generate` | Без сети перегенерирует только два каталога из принятого набора. |
| `npm run diff` | Загружает источники, проверяет кандидат, показывает отчёт и удаляет временные данные. |
| `npm run sync -- --dry-run` | Тот же предпросмотр. |
| `npm run sync` | Оставляет проверенную временную копию и выводит её путь. Не делает commit, push или PR. |

Успех и отсутствие изменений возвращают код 0; ошибки — ненулевой код. Неизвестные аргументы запрещены. Настройка DEBUG не включает вывод Git stderr или учётных данных.

Sync берёт базу из Git HEAD, а желаемый config — из рабочей папки. Остальные незакоммиченные изменения не переносятся и не меняются. Изменения пакетов и каталогов подготовлены в индексе временной копии; config скопирован как вход проверки, но не добавлен в индекс. Публикация конфигурации и принятие зеркала — отдельные изменения. После изучения временная копия может быть удалена целиком.

## Конфигурация

Файл [config/upstreams.json](config/upstreams.json) — единственный источник правды для имени и владельца каталога, источников, выбора пакетов и необязательных лимитов. После изменения config актуальный состав отражают только metadata и сгенерированные каталоги, а не этот текст.

- `type: "marketplace", selection: "all"`: все записи `.claude-plugin/marketplace.json`; необязательный `exclude: ["plugin-name"]`.
- `type: "marketplace", selection: "selected"`: только `plugins: [{ "name": "plugin-name" }]`; пустой список разрешён.
- `type: "repository", selection: "selected"`: у каждого плагина дополнительно обязателен `path`, например `"."` или `"plugins/example"`.
- Источник или выбранный плагин можно выключить через `enabled: false`. По умолчанию он включён.

Полный пример прямого источника:

```json
{
  "marketplace": { "name": "my-marketplace", "owner": { "name": "Example" } },
  "sources": [{
    "id": "example",
    "type": "repository",
    "repository": "example/plugins",
    "branch": "main",
    "selection": "selected",
    "plugins": [{ "name": "example-plugin", "path": "plugins/example" }]
  }],
  "limits": { "maxFileSizeMb": 5, "maxPluginSizeMb": 20 }
}
```

Одна единица лимита — 1 048 576 байт. Превышение лимита, небезопасная ссылка, submodule, LFS-указатель, опасный путь или исполняемый бинарник блокируют весь кандидат. Отслеживаемые `dist`, `.github`, `node_modules`, лицензии и скрипты сохраняются как данные. Зависимости плагинов не устанавливаются.

Добавление источника или изменение выбора допускается без немедленной замены опубликованных пакетов. `generate` всегда использует текущую metadata; изменение имени/владельца самого каталога требует регенерации. Исчезновение плагина upstream не равно разрешению удалить его: требуется явное изменение config.

Для marketplace-записей Claude сохраняются поддерживаемые только каталогом поля LSP: `strict`, `lspServers`, описание и версия. Эти поля не публикуются в каталоге ChatGPT/Codex, пока для него не заявлен отдельный LSP-формат.

`metadata/<name>.json` хранит источник, принятую ревизию и SHA-256 путей, байтов и Git modes. Новый upstream SHA без изменения этих данных не меняет metadata. Адреса внутренних symlink сохраняются побайтово с Git mode `120000`; файл-цель учитывается отдельно. На Windows временная копия хранит адрес ссылки как текстовый файл. Если checkout преобразует её в CRLF-файл и теряет mode в индексе, проверка сверяет этот placeholder с объектом из принятого Git tree; исполняемый mode читается из индекса. На других платформах создаются нативные ссылки. Работоспособность ссылок после установки в настольные клиенты ещё нужно проверить.

## GitHub CI и обновления

[Validate marketplace](https://github.com/krasnovmv/ai-marketplace/actions/workflows/validate.yml) запускается на PR, push в `main` и рабочие ветки `codex/**`, а также вручную. На Windows и Linux выполняются `npm ci`, тесты, проверка целостности и регенерация каталогов. Изменённые и неотслеживаемые каталоги приводят к ошибке. Проверка PR получает только право чтения репозитория; тесты и скрипты импортированных плагинов не выполняются.

[Sync upstream plugins](https://github.com/krasnovmv/ai-marketplace/actions/workflows/sync.yml) запускается вручную и после изменения `config/upstreams.json` в `main`. Он читает доверенный код основной ветки, проверяет весь кандидат и создаёт либо обновляет один PR из `bot/plugin-sync`. При отсутствии изменений коммита нет. Устаревший PR закрывается только после успешного полного сравнения. Сдвиг основной или bot-ветки и чужие коммиты останавливают публикацию. Принимать PR нужно вручную.

Для создания PR настройка GitHub **Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests** должна разрешать создание PR. Workflow использует встроенный `GITHUB_TOKEN`, отдельный PAT не нужен. Права записи выдаются только заданию sync. Для проверки bot-ветки sync явно вызывает `workflow_dispatch` у `validate.yml`: обычный push от `GITHUB_TOKEN` не запускает новый push workflow. Это поведение описано в [документации GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow).

Расписание — ежедневно в 04:00 UTC (07:00 по Москве). Оно защищено переменной репозитория `MARKETPLACE_SYNC_ENABLED`: значение `true` включает расписание после приёмки настольных клиентов. Ручной запуск и запуск после изменения config доступны независимо от этой переменной. Работа выполняется на GitHub runners и не требует включённого локального компьютера.

## Каталоги и приёмка

Генерируются `.claude-plugin/marketplace.json` и `.agents/plugins/marketplace.json`; оба ссылаются на `plugins/<name>` от корня репозитория. Форматы сверены с [документацией Claude](https://code.claude.com/docs/en/plugin-marketplaces) и [OpenAI](https://developers.openai.com/plugins/build/plugins#how-local-marketplaces-work).

Установка в Claude Desktop и ChatGPT desktop пока не проверена. До завершения приёмки нельзя обещать совместимость или автообновление. План проверки: подключить зеркало, установить пакеты из текущих каталогов, принять изменение навыка при прежней upstream version, выполнить штатное обновление и сверить фактически загруженные файлы. Версия/режим каждого приложения и необходимые действия будут записаны по результатам; кеши вручную не редактируются.

Общие правила разработки находятся в [AGENTS.md](AGENTS.md). План и прогресс OpenSpec находятся в [openspec/changes](openspec/changes).
