# Spec Delta

## Purpose

Автоматизация обновляет зеркало через один проверяемый PR и не требует регулярного ручного запуска или push.

## ADDED Requirements

### Requirement: Проверка PR

Workflow validate SHALL запускаться на каждый PR, проверять синтаксис config, целостность текущей metadata/пакетов и точность обоих каталогов, включая незакоммиченные и неотслеживаемые выходные файлы. SHALL не требоваться сеть к upstream или секреты записи. Изменение только config SHALL допускаться как изменение желаемого состава; согласованность самого опубликованного набора остаётся обязательной.

#### Scenario: Config-only PR

- **WHEN** пользователь добавил источник, сохранив текущие пакеты и каталоги
- **THEN** проверка проходит при валидном config и целом принятом наборе; копировать новые плагины вручную не нужно

#### Scenario: Правка каталога

- **WHEN** PR меняет manifest вопреки текущей metadata и пакетам
- **THEN** проверка падает с diff

### Requirement: Автоматический запуск

Workflow sync SHALL запускаться ежедневно в 04:00 UTC, вручную и после принятия изменения `config/upstreams.json` в default branch. SHALL использоваться доверенный код и config из default branch, отдельная копия и проверка целого результата. Автоматизация SHALL создавать либо обновлять один PR из `bot/plugin-sync` и никогда не делать прямой push в default branch или автоматический merge.

#### Scenario: Обновились файлы

- **WHEN** sync обнаружил изменение файлов выбранного пакета и все проверки прошли
- **THEN** бот публикует общий PR без локального запуска или push пользователем

#### Scenario: Принята конфигурация

- **WHEN** config-only PR принят
- **THEN** бот запускается и предлагает приведение зеркала к желаемому составу

### Requirement: Только содержательные изменения

При неизменном config автоматический PR SHALL создаваться только при добавлении, удалении или изменении файлов/mode выбранных пакетов; смена только upstream SHA и время проверки не создают diff. При явном изменении config допустим PR, меняющий состав или настроенное происхождение даже при одинаковых байтах. No-op SHALL не создавать коммит/PR; устаревший bot PR при успешном полном сравнении закрывается с объяснением.

#### Scenario: Обновился соседний плагин

- **WHEN** SHA источника новый, файлы выбранных пакетов прежние
- **THEN** metadata остаётся прежней и PR не создаётся

#### Scenario: Новый пакет в all

- **WHEN** upstream добавил плагин в зеркалируемый целиком marketplace
- **THEN** бот предлагает его файлы и записи каталогов в PR

### Requirement: Публикация целого набора

PR SHALL показывать добавления/изменения/удаления, старые/новые SHA и ссылки на источник. Ошибка любого выбранного пакета/источника SHALL оставлять bot-ветку и существующий PR неизменными; частичные результаты не публикуются. В commit SHALL включаться только управляемые пакеты, metadata и каталоги.

#### Scenario: Один источник недоступен

- **WHEN** первый источник обновился, второй не загрузился
- **THEN** workflow завершается ошибкой без изменения PR

### Requirement: Права и конкуренция

Запуски sync SHALL сериализоваться; перед публикацией SHALL проверяться актуальность default branch и ожидаемое состояние bot-ветки. Устаревший результат не публикуется. Чужие коммиты в bot-ветке SHALL не перезаписываться молча. Секреты записи SHALL не передаваться проверке внешнего PR; код плагинов SHALL не исполняться.

#### Scenario: Гонка с merge

- **WHEN** во время подготовки сместилась default branch
- **THEN** публикация отменяется либо результат пересобирается от новой базы

#### Scenario: Два запуска

- **WHEN** ручной sync стартует во время планового
- **THEN** bot-ветку не изменяют одновременно
