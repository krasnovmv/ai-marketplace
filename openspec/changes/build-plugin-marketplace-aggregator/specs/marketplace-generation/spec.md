# Spec Delta

## Purpose

Генерация делает единое зеркало доступным для установки в Claude Desktop и ChatGPT desktop без изменения исходных пакетов.

## ADDED Requirements

### Requirement: Два каталога одного зеркала

Система SHALL генерировать `.claude-plugin/marketplace.json` и `.agents/plugins/marketplace.json` из принятого либо подготовленного проверенного набора metadata и его пакетов. Оба каталога SHALL ссылаться на те же локальные `plugins/<name>/`, а не на изменяемый upstream. Имена SHALL быть уникальными. Для Claude source имеет вид `./plugins/<name>`; для ChatGPT — объект `{source: "local", path: "./plugins/<name>"}`. Пути SHALL разрешаться от корня marketplace-репозитория.

#### Scenario: Стартовый набор

- **WHEN** проверены ponytail и mattpocock-skills
- **THEN** оба каталога содержат две записи, ведущие к одним и тем же копиям; запись OpenSpec отсутствует

#### Scenario: Config опережает зеркало

- **WHEN** принята конфигурация нового источника, но sync PR ещё не принят
- **THEN** generate сохраняет опубликованный состав по metadata и не создаёт ссылок на отсутствующие файлы

### Requirement: Стабильная генерация

Каталоги SHALL использовать config.marketplace для идентичности владельца/каталога, а метаданные пакета брать из локальной принятой копии. Выход SHALL сортироваться по имени, использовать стабильные ключи, два пробела, LF и конечный перевод строки. Генерация SHALL работать без сети, не меняя файлы плагинов.

#### Scenario: Перестановка записей

- **WHEN** порядок источников в config изменился без изменения значений
- **THEN** каталоги побайтово идентичны

#### Scenario: Метаданные только внешнего каталога

- **WHEN** upstream поменял description записи, но файлы пакета прежние
- **THEN** зеркало не создаёт изменение только ради внешнего описания

### Requirement: Граница поддержки

Система SHALL поддерживать обнаружение и установку зеркала в Claude Desktop и поддерживающем локальные плагины режиме ChatGPT desktop. Она SHALL не конвертировать навыки/hooks, не собирать собственную упаковку и не гарантировать работу неподдерживаемых клиентом функций. Невозможность установки конкретного пакета SHALL фиксироваться с причиной; успешная генерация JSON не считается проверкой клиента.

#### Scenario: Специфичная функция

- **WHEN** плагин установлен, но клиент не поддерживает его hook
- **THEN** исходные файлы сохранены; ограничение документируется без автоматической починки

### Requirement: Проверка доставки обновлений

Приёмка SHALL отдельно подтверждать для обоих клиентов подключение личного каталога, установку стартового набора и загрузку изменённой копии после принятия PR. SHALL фиксироваться приложение, версия/режим и необходимое штатное действие обновления или перезапуска. Изменение SKILL.md при прежней upstream-версии SHALL быть отдельной проверкой. Неподтверждённое автообновление SHALL не обещаться.

#### Scenario: Обновление при прежней версии

- **WHEN** принят PR с изменением навыка без изменения plugin version
- **THEN** после документированного обновления клиент использует новые файлы; устаревший cache выявляется как ограничение, а не успешная доставка
