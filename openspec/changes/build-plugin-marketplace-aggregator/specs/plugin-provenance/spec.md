# Spec Delta

## Purpose

Метаданные фиксируют происхождение принятой копии, позволяя проверять содержимое без коммитов ради сдвига upstream-ветки.

## ADDED Requirements

### Requirement: Происхождение принятой копии

Система SHALL создавать `metadata/<name>.json` с name, source.id/type/repository/branch/path/commit и integrity.contentHash. Полный commit SHA SHALL обозначать ревизию, из которой взята принятая копия. При новом пакете или изменении файлов SHALL записываться использованный SHA; upstream-версия сохраняется без искусственного повышения.

#### Scenario: Первая поставка

- **WHEN** новый пакет включён в результат
- **THEN** metadata содержит полный SHA, repository и path фактически прочитанной ревизии

### Requirement: Детерминированный хеш

SHA-256 SHALL учитывать относительные пути, байты всех зеркалируемых файлов и исполняемый Git mode в однозначном стабильном представлении. mtime, служебные Git-данные и время проверки SHALL не влиять на хеш.

#### Scenario: Изменение навыка

- **WHEN** изменились байты SKILL.md при прежней версии manifest
- **THEN** хеш меняется и пакет считается обновлённым

#### Scenario: Изменение mtime

- **WHEN** изменилось только время файла
- **THEN** хеш остаётся прежним

### Requirement: Отсутствие обновлений только ради SHA

При прежних файлах, mode и настроенном происхождении система SHALL сохранять прежнюю metadata побайтово, даже если проверяемая branch указывает на новый SHA. Новая проверенная ревизия и дата SHALL оставаться только в журнале. Отсутствие файловых изменений SHALL не создавать автоматический коммит или PR. Явная смена происхождения пользователем в config обрабатывается отдельно и не скрывается.

#### Scenario: Коммит вне выбранного пакета

- **WHEN** upstream SHA изменился, но хеш и идентичность источника прежние
- **THEN** статус UNCHANGED; metadata, manifest и Git diff неизменны

#### Scenario: Один из двух пакетов изменился

- **WHEN** оба прочитаны из нового SHA, но файлы изменились только у первого
- **THEN** metadata первого получает новый SHA; metadata второго сохраняет прежний

#### Scenario: Явная смена источника

- **WHEN** пользователь заменил repository при одинаковых байтах пакета
- **THEN** предложение отражает новое происхождение как следствие config, а не обычное обновление только ради SHA

### Requirement: Воспроизводимость

При одинаковых config, проверенных ревизиях, исходном принятом состоянии и версии генератора выход SHALL быть побайтово одинаковым. Генерируемые файлы SHALL не содержать текущего времени запуска.

#### Scenario: Повторный запуск

- **WHEN** повторена успешная синхронизация без новых данных
- **THEN** выходные файлы совпадают; пустой commit не создаётся
