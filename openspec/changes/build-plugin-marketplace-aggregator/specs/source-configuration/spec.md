# Spec Delta

## Purpose

Конфигурация определяет источники личного зеркала и позволяет выбирать целый маркетплейс либо отдельные плагины.

## ADDED Requirements

### Requirement: Явная конфигурация

Система SHALL читать `config/upstreams.json` с полями `marketplace` (name, owner.name), `sources` и необязательными `limits`. Источник содержит уникальный id, type (`marketplace` или `repository`), GitHub repository вида `owner/repo`, явную branch и enabled (по умолчанию true). Неверные типы, неизвестные поля и повторные записи SHALL отклоняться до сетевых запросов.

#### Scenario: Неверная конфигурация

- **WHEN** повторяется id либо repository содержит URL с учётными данными
- **THEN** команда возвращает ошибку с путём поля, не обращаясь к сети

### Requirement: Режимы выбора

Для marketplace поле selection SHALL явно задавать `all` или `selected`. В режиме all выбираются все записи manifest, кроме явно перечисленных имён в необязательном exclude; plugins запрещён. В режиме selected обязателен массив plugins с name и enabled (по умолчанию true), exclude запрещён. Для repository допустим только selected; каждой записи требуется path, включая `.`. Пустой выбранный список допустим. Система SHALL не выбирать режим по размеру источника.

#### Scenario: Новый плагин в целом маркетплейсе

- **WHEN** all-источник добавил новый плагин
- **THEN** он проверяется и включается в PR; основная ветка до принятия не меняется

#### Scenario: Новый сосед выбранного плагина

- **WHEN** selected-источник добавил неуказанный плагин
- **THEN** он не импортируется

#### Scenario: Новый навык внутри пакета

- **WHEN** выбранный плагин получил новый skill
- **THEN** он копируется как часть целого пакета и виден в PR

### Requirement: Управление составом

Отключение источника или выбранного плагина, удаление записи из config либо явное exclude в режиме all SHALL предлагать удаление соответствующих управляемых копий и metadata через PR. Config SHALL описывать желаемый состав, metadata — уже опубликованный; временное расхождение после изменения config допустимо и не требует ручного копирования плагинов.

#### Scenario: Добавление источника

- **WHEN** пользователь принял корректную конфигурацию нового источника
- **THEN** следующий sync предлагает его плагины в отдельном PR

#### Scenario: Отключение

- **WHEN** плагин явно отключён или исключён
- **THEN** до merge bot PR он остаётся в опубликованном каталоге; PR показывает его удаление

### Requirement: Стартовый набор и имена

Начальная конфигурация SHALL включать `DietrichGebert/ponytail` и `mattpocock/skills` в режиме all и не включать OpenSpec. Имена плагинов SHALL соответствовать `^[a-z0-9]+(?:-[a-z0-9]+)*$`, быть переносимыми между Windows/Linux и уникальными во всём зеркале. Коллизии SHALL давать ошибку с указанием обоих источников без автоматического переименования.

#### Scenario: Первая поставка

- **WHEN** разрешены стартовые marketplace
- **THEN** зеркало содержит пакеты ponytail и mattpocock-skills, а не отдельную запись на каждый skill; OpenSpec отсутствует

#### Scenario: Коллизия после расширения all

- **WHEN** новый пакет имеет имя уже выбранного пакета другого источника
- **THEN** весь запуск прекращается без публикации; сообщение предлагает явное исключение или изменение выбора

### Requirement: Секреты вне конфигурации

Публичные источники SHALL работать без токена; приватные используют аутентификацию окружения Git/CI. Секреты SHALL не храниться в config и не попадать в логи.

#### Scenario: Недостаточные права

- **WHEN** приватный источник недоступен
- **THEN** команда сообщает источник и ошибку доступа без вывода учётных данных
