# Spec Delta

## Purpose

Команды позволяют проверять зеркало и предлагать обновления локально, сохраняя рабочие файлы пользователя.

## ADDED Requirements

### Requirement: Команды и границы записи

Проект SHALL предоставлять `pnpm sync`, `pnpm validate`, `pnpm generate`, `pnpm diff`. sync готовит проверенный результат в отдельной копии и выводит её путь; самостоятельно не делает push/PR. validate проверяет config, целостность принятого набора и его каталоги без сети и записи. generate обновляет только два каталога из текущей metadata. diff выполняет предпросмотр без сохранения результата. Успех/no-op SHALL возвращать 0, ошибка — ненулевой код.

#### Scenario: Локальный sync

- **WHEN** пользователь запускает sync с незавершёнными изменениями в своей рабочей папке
- **THEN** создаётся отдельный результат; исходные файлы, индекс и ветка остаются прежними

#### Scenario: Локальная проверка

- **WHEN** metadata не соответствует файлам пакета
- **THEN** validate указывает путь и причину, не исправляя их

### Requirement: Предпросмотр

`pnpm sync --dry-run` и `pnpm diff` SHALL разрешать upstream и проверять тот же кандидат, что полный sync, но оставлять файлы проекта неизменными. Временные данные SHALL находиться вне проекта и удаляться после предпросмотра. Неизвестные аргументы SHALL отклоняться; выбор одного плагина через CLI не входит в MVP.

#### Scenario: Два обновления

- **WHEN** dry-run обнаружил два изменённых пакета
- **THEN** оба показаны в отчёте; ни один файл проекта не меняется

#### Scenario: Ошибка проверки

- **WHEN** diff обнаружил опасный путь
- **THEN** возвращается ненулевой код без публикации

### Requirement: Отчёт и желаемый состав

Система SHALL показывать source, имя и ADDED/UNCHANGED/UPDATED/REMOVED/BROKEN. Для изменённых пакетов выводятся старый и новый SHA; для UNCHANGED различаются SHA принятой копии и проверенный SHA. REMOVED SHALL отличать явное удаление по config от блокирующего исчезновения upstream. validate SHALL допускать желаемый состав config, ещё не синхронизированный с metadata, и сообщать о таком расхождении, если оно определяется локально. `DEBUG=1` SHALL не раскрывать секреты.

#### Scenario: Ожидающее добавление

- **WHEN** config указывает новый источник без принятой metadata
- **THEN** валидный текущий набор проходит validate; сообщение указывает необходимость sync

#### Scenario: Нет новых файлов

- **WHEN** SHA изменился без изменения файлов
- **THEN** отчёт содержит UNCHANGED и проверенный SHA; не показывает фиктивное обновление

#### Scenario: Сетевая ошибка

- **WHEN** fetch не удался
- **THEN** отчёт показывает BROKEN с источником и причиной без токена
